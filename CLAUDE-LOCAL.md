### 2026-09-24 (сессия 7 — «Гаммы»: настоящие 3nps-позиции вместо боксов на форме пентатоники)

**Контекст:** Денис спросил, правильно ли боксы натурального минора на вкладке «Гаммы» (сессия 6) соответствуют тому, как он учил гаммы у преподавателя — строго по 3 ноты на струне. Выяснилось, что нет: боксы сессии 6 брали форму пентатонического бокса и досыпали недостающие ноты лада в её же диапазоне ладов, отсюда неровные 2-3 ноты на струне. Через серию уточняющих вопросов (в т.ч. недопонимание с обеих сторон, роль «представь что ты мой препод») дошли до сути: Денис уже знал свою 3nps-гамму ДО создания приложения, поэтому она просто не попала в него — а не потому что боксы сессии 6 лучше для импровизации. Денис явно выбрал переделать «Гаммы» на настоящую 3nps (вариант А из двух предложенных), затем явно выбрал нумерацию 7 позиций по физическому месту на грифе (как у боксов пентатоники), а не по ступени лада — через AskUserQuestion с превью обоих вариантов.

**Что сделано:**
- **Новый генератор 3nps-позиций** (`get3npsPosition`/`get3npsPositions`/`get3npsAllFrets`, ~строка 776): считает 7 позиций напрямую по формуле лада (не от формы пентатоники), всегда ровно 3 ноты на струне; позиции сортируются по возрастанию нижнего лада на грифе.
- **`buildFretboard` получил флаг `isScalePos`**: классификация нот (пентатоника/добавленная/характерная) для «Гамм» теперь по принадлежности pitch-class к ладу (как уже было в режиме «Линейно»), а не по точному совпадению лада с формой пентатонического бокса. Вкладку «Пентатоника» (боксы 1-5 `AM_BOXES`/`AMAJ_BOXES` + опциональный оверлей лада `selScale`) НЕ трогали вообще — отдельный `drawScalePosOverlay` для рамок «Гамм» вместо правки общего `drawBoxOverlay`, чтобы не рисковать существующей вкладкой.
- **UI**: переключатель позиций 1-5→1-7 (`buildBoxSel`/`buildBoxLegend` получили опциональные `count`/`label`/`colors`, дефолты сохраняют старое поведение «Пентатоники»), новая палитра `SCALE_POS_COLORS` (7 цветов), подписи «Выбери позицию» / «ПОЗИЦИИ» / «Позиция N» / «Все позиции».
- **Проверено программно** (не на глаз): 7 ладов × 12 тональностей × 7 позиций — всегда ровно 3 разные ноты на струне в пределах грифа 0-17, без пропусков/дублей нот лада, объединение в ALL совпадает с суммой позиций; позиция 4 для Am эолийского сверена побайтово с формой, которую Денис знает от преподавателя (5-7-8/5-7-8/5-7-9/5-7-9/6-8-10/7-8-10 — совпадение 1-в-1); классификация penta/ext/char на этой же позиции сверена с теорией (F — характерная b6, B — добавленная 2-я ступень, остальное — пентатоника). Все проверки — на функциях, извлечённых прямо из `index.html` (не переписанных заново), чтобы ловить опечатки при переносе.
- **Фоновый `/code-review`** (запущен самим Денисом) багов не нашёл — только 2 находки на эффективность (`get3npsPositions` пересчитывался до 4 раз за один рендер вкладки; `get3npsAllFrets` дублировал тот же обход). Обе исправлены простым кэшем последнего результата в `get3npsPositions` + переиспользованием его из `get3npsAllFrets`; после фикса заново прогнаны все 84 комбинации — 0 ошибок.
- **Деплой**: `18acb2d`, запушено в main. Денис попросил задеплоить до живой приёмки — тестирует сам на живом Netlify-сайте («сервером пользуюсь только я»), не на локальном файле.

**Что решили:**
- Нумерация 7 позиций — по физическому месту на грифе (позиция 1 — самая нижняя), а не по ступени лада. Из-за этого знакомая Денису форма (начинается с тоники) — не всегда «Позиция 1», а зависит от лада/тональности (для A-эолийского это «Позиция 4»). Выбрано явно, с превью обеих раскладок.
- Старое решение сессии 6 (форма пентатоники + добавленные ноты) признано историческим артефактом, а не осознанным педагогическим выбором — переоценка не потребовала переголосования по цели приложения, только по реализации.
- Существующий режим «Линейно» (одна аппликатура от тоники через весь гриф, есть с более ранней сессии) не трогали — сосуществует с новым режимом «Позиции» без конфликта.
- Вкладка «Пентатоника» — зона, которую в этой сессии сознательно не трогали ни при каком из вариантов правок (явно проговорено дважды).

**Новые баги:** не найдено (обе находки код-ревью — эффективность, не корректность).

**Открытые вопросы:**
- Живая приёмка на реальном телефоне — Денис делает её сам после этой сессии, результат неизвестен на момент записи.
- Не обсуждали, не стала ли «Линейно» частично избыточной рядом с «Позициями» (та всегда показывает форму от тоники, эти — по физическому месту) — не поднималось как проблема, но стоит иметь в виду.

**Что осталось:** см. «Что осталось» в «Текущем фокусе» — приёмка новых 3nps-позиций «Гамм» первым пунктом вместо старой формулировки сессии 6, дальше старый хвост без изменений.

### 2026-09-14 (сессия 6 — вкладка «Гаммы»: боксы-аппликатуры по 7 ладам + код-ревью + сверка теории)

**Контекст:** Денис попросил добавить шпаргалку по гаммам/ладам, аналогичную аккордовой и пентатоник-шпаргалкам — свой раздел, а не только оверлей поверх текущего бокса пентатоники (то, что уже было с сессии 1). Формулировка запроса напрямую задевала записанное в этом же файле решение «не добавлять справочник всех ладов без применения» — это подсвечено явно; Денис не понял формулировку, получил объяснение (речь про текст-теорию для чтения, а не про играбельные аппликатуры) и подтвердил, что его запрос ей не противоречит. Дальше — обычный цикл: уточняющие вопросы (формат — как боксы пентатоники; размещение — новая вкладка) → план → подтверждение → реализация → тесты → фоновый `/code-review` (запущен самим Денисом) → фикс найденного → коммит → пуш. Отдельным заходом после деплоя Денис попросил сверить гаммы с эталонной теорией.

**Что сделано:**
- **Новая вкладка «🎶 Гаммы»** (третья, рядом с «Пентатоникой»/«Аккордами»): тональность → лад (7 кнопок) → бокс (1-5/ALL) → гриф с аппликатурой лада (тоника/нота пентатоники/нота лада/характерная нота — те же цвета, что в оверлее «Расширь до гаммы») → карточка с нотами, характерной нотой, жанром, советом по обыгрыванию.
- **Рефакторинг ради переиспользования**: `getActiveFrets`/`currentBoxes`/`pentaIntervals` получили явный параметр `mode`/`key` вместо чтения глобальных `selKey/selMode`; построение грифа и SVG-рамок боксов вынесено в параметризуемые `buildFretboard`/`drawBoxOverlay`, используются обеими вкладками без дублирования ~150 строк.
- **Код-ревью нашёл 4 проблемы, все исправлены**: (1) `renderGamma()` не гасил зажатые ноты перед перерисовкой грифа (в отличие от `render()` основной вкладки) — на телефоне при смене лада с зажатой ноты нота могла звучать бесконечно, кнопка исчезала с экрана вместе со старым грифом, гасить было нечем; (2) `setTimeout(drawBoxOverlay,30)` в режиме ALL захватывал лад в замыкание на момент клика — при очень быстром двойном тапе рамка бокса на кадр могла показать не тот лад; (3) `setNoteLabels()` безусловно перерисовывал невидимый гриф «Гамм» при каждом клике по Ноты/Интервалы на любой вкладке; (4) 4 маленькие функции-отрисовщика («Гаммы») дублировали код аналогов на «Пентатонике» вместо переиспользования — по явной просьбе Дениса («почистить сейчас» на вопрос об этом, против моей рекомендации оставить) вынесены в общие `buildKeyGrid`/`buildBoxSel`/`buildBoxLegend`/`buildScaleSel`/`buildScaleInfoCard`.
- **Сверка музыкальных данных с эталоном**: все 7 ладов `SCALES` — корректные ротации мажорной гаммы, характерные ноты и их подписи верны (включая нюанс лидийского — тритон подписан как «#4», а не общей таблицей «b5»), пентатоника вкладывается в лад везде кроме локрийского (уже задокументированное исключение — нет чистой квинты). Расхождений не найдено.
- **Проверки:** 30 assert'ов в jsdom (структура вкладки, корректность нот для нескольких тональностей/ладов/боксов, регрессия «Пентатоники» и её оверлея после рефакторинга, тоггл-выключение лада кликом, зависшая нота — целевой тест на баг из ревью, сохранение/восстановление состояния вкладки из localStorage) + отдельный программный свип 504 комбинаций тональность×лад×бокс (без исключений, все ноты внутри лада) + отдельный скрипт сверки `SCALES` с эталонной теорией. Всё в scratchpad, в проект не попало (проверено — дублирующих объявлений функций нет).
- **Деплой:** два коммита — `64e5520` (сама фича) и `cea7768` (отдельно, накопившееся с прошлой сессии обновление лога CLAUDE.md по сессии 5, так и не закоммиченное тогда).

**Что решили:**
- Формулировка «не добавлять справочник всех ладов» уточнена (см. «Текущий фокус» и «Чего НЕ добавлять» выше) — запрет про теорию-простыню для чтения, не про играбельные аппликатуры на грифе.
- Формат новой вкладки — «как боксы пентатоники» (аппликатуры на грифе), а не «как аккорды» (генератор по запросу); размещение — отдельная вкладка, не раздел внутри «Пентатоники».
- Общий тумблер Ноты/Интервалы у «Гамм» и «Пентатоники» — не стали заводить отдельный.
- Дублирование четырёх мелких функций-отрисовщиков из код-ревью — почистить сразу, а не откладывать (выбор Дениса против моей рекомендации «оставить, риск важнее пользы»).

**Новые баги:** не найдено (все проблемы из код-ревью — из кода этой же сессии, исправлены до деплоя, не регрессии старого).

**Открытые вопросы:**

- Остальной хвост приёмок (дисторшн, джем, минусовка, ALL-режим на телефоне, пересекающиеся прогрессии) не сдвинулся — по-прежнему ждут своей сессии.

**Что осталось:** см. «Что осталось» в «Текущем фокусе» — приёмка «Гамм» первым пунктом, дальше старый хвост без изменений.

### 2026-09-02/03 (сессия 5 — дисторшн как рок-гитара: пауэр-аккорды, глушение струн, палм-мьют)

**Контекст:** Денис снова пожаловался на дисторшн («нравится как в Songsterr, реально сделать аналог?»), затем уточнил главное: **в рок-прогрессиях всё превращается в кашу вместо ритмического рисунка**. Дальше сессия шла циклами «сделать демо → послушать → отвергнуть»: GM-банки сэмплов → записанные пауэр-аккорды реальной гитары → вылеченный синтез (выбран). Отдельно Денис поймал две методические ошибки: (1) первое демо «текущего звука» я собрал реконструкцией цепи по коду, и оно звучало не как приложение; (2) все серии записывались на `RHYTHMS.rock[0]` = «Восьмые», под которые ритм оценить невозможно. Обе исправлены по ходу.

**Что сделано:**
- **Метод записи звука** (главное приобретение сессии): вместо реконструкции цепи — **захват мастер-выхода живого `index.html`** в headless Chrome (патч `AudioNode.prototype.connect` перехватывает всё, что идёт в `ctx.destination`, и дублирует в `ScriptProcessor`; запись ресемплится честным `OfflineAudioContext`). Теперь «как звучит приложение» — это факт, а не пересборка. Прототипы фич делались инжектом патчей в живую страницу (`scratchpad/inject.js`), а не правкой проекта.
- **Метрики каши** вместо «на слух»: полифония (сколько голосов звучит одновременно, из лога `makeVoice` с учётом глушения) и **глубина провала между ударами в дБ** (медиана по огибающей) — прямая мера читаемости ритма. До правок: 28 голосов, провал −2.8 дБ.
- **Диагноз** (`54d2cbe` чинит всё перечисленное): бой брал полное трезвучие с терцией в C3–B3 (`chordNotes`) — терция через перегруз даёт интермодуляционную грязь, это и слышалось как «электропианино»; ноты жили до конца такта (`scheduleBar`, до 1.6 с) и не глушились следующим ударом; у дисторшн-голоса **вообще не было затухания по длительности** — `opts.dur` задавал только длину KS-буфера, звук обрывался его концом; уровень голоса 0.9 × полифония вдавливал общий перегруз в тотальный клип.
- **Правки в `index.html`:** новая `strumNotes()` (пауэр-аккорд тоника+квинта+октава, октавой ниже, диапазон 38–49; `chordNotes` НЕ тронута — подсветка грифа по-прежнему получает полный аккорд с терцией); реестр `ringingStrings` (новый удар гасит предыдущий голос той же ноты за 35 мс через `cancelAndHoldAtTime` с фолбэком); палм-мьют `PALM_MUTE_DUR` 0.19 с в бое; `DIST_VOICE_GAIN` 0.18 вместо 0.9; `DIST_RELEASE` 0.09 + буфер длиннее ноты; `post` буса 0.62 → 0.9 (калибровка по RMS к акустике, 1.07×); в `RHYTHMS.rock` первым поставлен «Драйв» вместо «Восьмых».
- **Проверки:** 12 структурных assert'ов (состав аккордов во всех 12 тональностях × всех прогрессиях, регистр, константы, порядок ритмов, громкость тембров) + 7 smoke (гриф, лики, акустический бой, смена тембра в лупе, восстановление состояния) + запись боевого выхода: полифония 3 вместо 28, провал −4.5 дБ, совпадение с одобренным прототипом 0.2 дБ.
- **Отвергнутые направления** (проверены, не выброшены зря — см. «Что решили»): 9 GM-банков WebAudioFont (0290/0300, от 144 КБ до 1 МБ) и записанные пауэр-аккорды реальной гитары (пак Ax_Grinder, freesound, CC BY 3.0).
- **Артефакт для приёмки** (4 итерации, один URL): https://claude.ai/code/artifact/6780cef7-b230-46be-a33e-a1cf558cef05 — плееры с осциллограммами и метриками.

**Что решили:**
- **Сэмплы отвергнуты дважды, оба раза на слух Дениса.** GM-банки: чище по цифрам (провал до −10.8 дБ), но «пластмасса». Записанная гитара: та же природа, что у Songsterr, но одна и та же запись, транспонированная по высоте, звучит одинаково на каждом ударе — синтез выигрывает микровариативностью (KS генерирует струну заново). Итог: **рабочий вариант — вылеченный синтез**, направление сэмплов закрыто.
- **Терция в дисторшне не нужна** — формулировка Дениса: «пауэр-аккорд на то и пауэр-аккорд, что у него нет минора или мажора». Наклонение остаётся на подсветке грифа и басу.
- **Объём правки** — только то, что Денис слышал (без кабинет-IR): сначала живая приёмка, потом решение про кабинет.
- **Дефолтный ритм рока** — «Драйв» (6 ударов с синкопой) вместо «Восьмых».
- Синтез не спасается доводкой в пределах текущей архитектуры: при 3 голосах, палм-мьюте и правильном гейн-стейджинге провал так и остался −3.1 дБ. Короткая нота KS — ещё шум, а не тон; кабинет и лимитер подтягивают паузы. Это потолок, который стоит помнить при следующих жалобах на звук.

**Новые баги:** своих регрессий не поймано (все проверки зелёные). Найдено и исправлено в этой же сессии: отсутствие затухания дисторшн-ноты по `dur` (существовало с сессии 4), монотонный дефолтный рок-ритм.

**Открытые вопросы:**
- Новый дисторшн ушами не слушали — только цифры и совпадение с прототипом.
- Нужен ли кабинет-IR — решать после приёмки.
- Первый паттерн в blues/pop/funk/reggae на монотонность не проверялся.
- Смена порядка `RHYTHMS.rock` сдвигает сохранённые в `jamPrefs` индексы: у существующих пользователей выбранный ритм съедет на один. Не ломает, но при первом запуске может играть не тот рисунок.

**Что осталось:** см. «Что осталось» в «Текущем фокусе» — приёмка нового дисторшна первым пунктом.

### 2026-07-19 (сессия 4 — полный аудит, джем-движок + «Мои джемы», новый дисторшн, минусовка)

**Контекст:** Денис попросил полный аудит приложения с headless-тестированием всех функций, оценкой UX и пробелов; отдельно пожаловался на звук дисторшна («Songsterr передаёт лучше») и спросил про загрузку треков. По итогам аудита сам предложил «джем-треки», выбрал вариант А+Б, затем выстроил очередь: джем-треки → дисторшн (вариант А, KS) → конструктор прогрессий (поглощён «Моими джемами») → загрузка минусовки (выбрал «в очередь» вместо рекомендованного «не делать»). Каждый большой шаг — план → подтверждение → «заливать?» → деплой.

**Что сделано:**

Конструктор без ввода текста: качество (МАЖОР/МИНОР/7/m7 → q='I'/'i'/'I7'/'i7') + тап по нотам → цепочка пилюль (тап убирает) + жанр + автоимя из аккордов. Аккорды хранятся АБСОЛЮТНО (d = pitch class от C, ri=0 при игре) — смена тональности грифа джем не транспонирует (осознанно: это песня, а не паттерн). У имён своих джемов отключён CSS-капс (иначе «Am» читается как «AM»).
- **Новый дисторшн** (`6924868`): источник — Karplus-Strong (damping 0.9985 — медленное затухание, сатурация дожимает в «поющий» сустейн) + второй голос +6 центов (биения, тот же буфер через detune — бесплатно). Цепь буса: hp 75 → lp 6000 → drive 2.2 → tanh k=3 → lp 4200 (межкаскадный физз) → drive 1.6 → tanh k=6 → ConvolverNode с синтезированным IR кабинета (`cabIR`: импульс + затухающий шум через двойной lowpass 4.5кГц и highpass 90Гц, 50мс) → peaking 550Гц +3.5дБ → post 0.62. «Укус» атаки: огибающая 1.35×→0.6× за 0.3с + щелчок медиатора 0.33 (мимо перегруза). **Калибровка не на глаз:** оффлайн-рендер старой/новой цепи и акустики в OfflineAudioContext реального Chrome, RMS-замеры; post 0.62 выравнивает дисторшн с акустикой (тело 0.083 vs 0.081, нота 0.071 vs 0.068 — переключение тембров без скачка громкости; старая цепь была громче акустики в 1.5 раза). Сустейн: RMS хвоста 0.082 против 0.003 у пилы.
- **Минусовка** (`d69c879`): блок «6. Минусовка» — загрузка audio/*, плеер (▶/⏸/⏹, перемотка тапом по бару), A-B луп (маркеры в текущей позиции, sample-accurate через loopStart/loopEnd, зона видна на баре), громкость трека.
